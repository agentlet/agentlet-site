# /cdn

`/cdn/v1/` hosts everything the live demo can download: the built
agentlet-core distribution, the pdf.js worker it needs, the demo agentlet
bundles, the agentlet registry, and the demo loader itself (see
`/docs/live-demo/`). Nothing the live demo needs lives outside this path, so
a page only ever has one origin-relative prefix to allow for it.

Everything under `/cdn/v1/` is generated by `scripts/build-cdn.mjs` from
`src/agentlets/manifest.ts`, the single source of truth for which agentlets
exist. It is not committed: `npm run build` and `npm run dev` both run the
generator first (see the `prebuild`/`predev` scripts in `package.json`), so
`/cdn/v1/` always reflects the current source. Do not add files here by
hand; edit `src/agentlets/` and let the build regenerate this directory.

## Contents

- `agentlet-core.min.js`: copied from `node_modules/agentlet-core/dist/`,
  unmodified.
- `pdf.worker.min.mjs`: copied from `node_modules/agentlet-core/dist/`, the
  matching pdf.js worker agentlet-core 2.1.0 ships alongside
  `agentlet-core.min.js`. No separate version to pin.
- `agentlets/<name>.js`: one esbuild IIFE bundle per `src/agentlets/*.ts`
  module (except `manifest.ts` and `shared.ts`, which are bundled into each
  module rather than shipped on their own). Never bundles `agentlet-core`
  itself, which stays a runtime global.
- `agentlets-registry.js`: generated in agentlet-core's registry script
  format (see `/docs/guides/script-injection/`), listing every entry from
  `src/agentlets/manifest.ts`. Dispatches its `agentletRegistryLoaded` event
  synchronously (no `setTimeout`); see the comment on `buildRegistry()` in
  `scripts/build-cdn.mjs` for why.
- `demo-loader.js`: esbuild bundle of `src/scripts/demo-loader.ts`. The only
  file any page ever loads directly (the hero button, the bookmarklet, or
  the tiny inline reopen script every page carries, see
  `src/scripts/agentlet-inline-snippets.mjs`); everything else above is
  loaded by this file or by agentlet-core itself.
